# N0 專案結構

## 目錄

| 路徑 | 內容 |
|---|---|
| `platform/` | `daphne_platform` 靜態庫：作業系統相關的服務（執行緒排程、浮點控制、環境變數、快取資料夾、開檔），N25 |
| `dsp/` | `daphne_dsp` 靜態庫：訊號處理區塊、濾波器設計、雙倍精度（double-double）運算、平行化工具 |
| `core/` | `daphne_engine` 靜態庫：解碼器、處理鏈、裝置輸出（Windows：WASAPI、ASIO；macOS：Core Audio；其他平台沒有輸出，`output_none.cpp`）、播放器 |
| `capi/` | `daphne_core` 共享庫（C API，函式前綴 `dc_*`，標頭 `capi/daphne_core.h`） |
| `cli/` | `daphne` 命令列工具（播放、轉檔、量測用） |
| `helper/` | `daphne-helper`：播放器當作子程序，stdin / stdout 一行一個 JSON（macOS MIKU 用，N4「helper」） |
| `src/Daphne.Extension/` | Windows MIKU 擴充（C#，經 P/Invoke 呼叫 `daphne_core.dll`）；`build_for_miku.ps1` 由它的建置呼叫 |
| `miku/` | macOS MIKU 模組（JavaScript：`engine.js` 經 `helper-client.js` 驅動 `daphne-helper`）與 `pack-mac.sh`（打包給 MIKU 的 Mac 安裝程式，N25） |
| `fuzz/` | libFuzzer 目標：`fuzz_decoder`（dr_wav / dr_flac / minimp3）、`fuzz_dsd`（DSF / DFF 讀取）；種子在 `corpus/`（`make_seeds.py` 產生），N25 |
| `tests/` | `daphne_tests`（Catch2 單元測試；播放器以假裝置測試，`tests/fake_output.h`）；ctest `helper_closed_stdout`（macOS / Linux：stdout 先關閉時 helper 不被 `SIGPIPE` 結束）；`miku_engine.js`（Mac 外殼 `miku/engine.js` 對假的 helper，`node tests/miku_engine.js`，CI 的 linux job 與 `node --check miku/*.js` 一起跑） |
| `.github/workflows/` | CI：`build.yml`（Windows、Linux、Linux + FFmpeg、macOS 建置與單元測試，警告視為錯誤）、`sanitizers.yml`（Linux：ASan + UBSan、TSan、libFuzzer），N25 |
| `verify/` | Python 驗證腳本（需要 numpy、soundfile、ffmpeg 在 PATH）；`live.py` 另需 sounddevice 與 VB Hi-Fi Cable |
| `tools/` | `sdm_design.py`：DSD 調變器係數設計（需要 python-deltasigma、numba、scipy；`sdm_design.py 8:64` 只重新設計指定的列） |
| `third_party/` | dr_libs、minimp3、Catch2、nlohmann/json（C API 與 helper 的 JSON）、FFmpeg（共享開發包）、ASIO SDK |
| `scripts/` | `build.cmd`（Release 建置 + 單元測試）、`fetch_ffmpeg.ps1`（本 repository release 的 FFmpeg，檢查 SHA-256）、`fetch_asiosdk.ps1`、`build_for_miku.ps1`（給 MIKU 的 `daphne_core.dll`；沒有 Visual Studio / CMake 時用 `fetch_msvc.ps1`、`fetch_cmake.ps1`、`fetch_ninja.ps1` 下載可攜版，N25） |
| `.tools/`（不進版控） | `build_for_miku.ps1` 與 `pack-mac.sh` 下載的建置工具 |

## 訊號流程（N1–N24）

圖例：

- `|`、`v`、`-`、`+`：訊號路徑；`+` 是分岔或匯合點。
- `<..` / `..>`：N7 / N8 提供濾波器係數，不在訊號路徑上。
- 最右邊的直線：DSD 檔直送，不經任何處理，直接進 N20。
- `source rate` 括起的三級在來源取樣率執行，兩種核心相同。

N4（播放整合）是整條流程的外框：在 N6 決定核心與裝置格式、建立處理鏈、執行無縫換軌與設定變更，並在處理執行緒上把每個區塊從 N1 推到 N23。N9–N14 未使用（編號保留）。

## 命名

- 命名空間：`daphne`（引擎）、`daphne::dsp`（訊號處理）、`daphne::platform`（作業系統服務）。
- include 路徑：`daphne/engine/...`、`daphne/dsp/...`、`daphne/platform/...`。
- 編譯巨集：`DAPHNE_HAVE_FFMPEG`、`DAPHNE_HAVE_ASIO`，由 `core/CMakeLists.txt` 偵測 `third_party/` 是否有對應套件後定義。
- 第三方 include 透過 INTERFACE target `daphne_vendor` 提供。

## 建置

```
scripts\build.cmd                                   （Windows）
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release      （任何平台，N25）
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

- C++20。Windows：MSVC，x64，`/W4`，Unicode；macOS / Linux：Clang / GCC。
- 輸出在 `build/bin/`（Visual Studio 為 `build/bin/Release/`）；FFmpeg DLL 於建置後自動複製到執行檔旁。
- Windows 上命令列程式與測試以 `wmain` 進入（`/ENTRY:wmainCRTStartup`）；引擎的路徑一律是 `std::filesystem::path`（Windows 為 UTF-16），命令列參數轉成 UTF-8（N25）。
- FFmpeg 的位置是 CMake 快取變數 `DAPHNE_FFMPEG_DIR`（預設 `third_party/ffmpeg`，`include/` 與 `lib/`；`pack-mac.sh` 為每個架構各建一份並傳入）。macOS / Linux 在那裡找不到時改用 pkg-config 找已安裝的開發套件。
- 都沒有 FFmpeg 時仍可建置，但只剩 WAV / AIFF / FLAC / MP3 / DSD。

## 驗證流程

每個節點完成後：

1. `scripts\build.cmd`（或上面的 cmake / ctest）：建置 + 單元測試，不可有警告。
2. `python verify\<節點>.py`：對實際檔案或訊號做端到端量測（`decoders.py`、`filter_design.py`、`dsd_files.py`、`live.py`）。
3. 結果寫進對應的 `doc/NX_*.md`。
